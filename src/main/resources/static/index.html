系统设置

改完点保存立即生效，不用重启、不用登服务器改文件。 标着「重启生效」的项例外——它们只在启动时读一次，热改会让已经跑起来的采集和库里的历史对不上。
只能改配置文件（这里故意不给开关）
演示数据
开关只管「下次启动要不要生成」，已经生成的假数据必须在这里清掉， 否则客户看到的是编出来的电费和产量。清除不可恢复，只删演示期间灌的数据。

联网检查更新

点「检查更新」从配置的更新源（国内/国外镜像）问一下有没有新版本。只检查，不会自动装。

升级包

升级包由供应商签名，签名不对装不进去

应用与回滚

升级会中断采集约 10~30 秒，建议挑换班或停机时段。替换的是程序文件， data 目录里的历史数据不会动。 回滚只恢复上一个 jar，不恢复数据库——所以带数据库结构变更的版本要谨慎。

数据库结构

升级包里的 migration.sql 在启动时自动执行
执行时机是「换完 jar、服务启动的那一刻」，抢在 Hibernate 建列之前—— 否则给已有表加非空列时，Hibernate 会先试一次必然失败的 alter，服务直接起不来。
脚本里如果出现 drop database、drop schema 或不带条件的 delete，会被拒绝执行并在这里红灯显示，需要供应商改包重发。
迁移失败不会拦住服务启动（车间不能因为一次改表就没监控），但这里会一直红着，别当没看见。

基本电费 / 需量设置

大工业电费 = 电度电费（用了多少度）+ 基本电费（占了多少容量或需量）+ 力调电费。 基本电费每月固定交，两种算法：按需量按当月最大 15 分钟平均功率算， 按容量按变压器容量算。数字都在供电合同和电费单上。

告警规则

规则决定「什么情况算报警」。默认只开了「离线」和「报警信号」两条——这两条基本不会误报。 停机类规则要先想清楚你们厂几点上班、机器正常停多久，不然晚上全厂一起报。
多个用逗号分隔，支持 CNC-* 这种通配
条件要连续成立这么久才报警
条件消失后再观察这么久才判恢复，防止临界值反复跳
恢复后这段时间内不再重复报同一台
支持跨零点，如 20:00-06:00（夜班）
全不勾 = 每天。必须勾，否则这条规则不会触发
