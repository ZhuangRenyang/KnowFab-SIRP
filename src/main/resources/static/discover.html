第一步 · 扫网段找设备

并发测一批 C 段里谁开着 Modbus 端口。同一局域网内，千台规模十几秒出结果； 大厂设备跨多个网段就全填上（逗号隔开），单次上限 1024 台，更多分几批。
扫的是本机所在网络——确认服务器和设备网线/WiFi 在同一路由下。
IP 地址端口操作
这个范围里没有开着该端口的设备

第二步 · 读寄存器对拍找点

对扫描到的 IP 读一段寄存器，勾上自动刷新（2 秒一次）， 然后去设备边：启动机器 → 看哪个值变了；停机再看；报警再看。 跟着状态走的 0/1/2 就是运行状态，单调递增的是产量计数，报警时非 0 的是报警字。
一台盒子后面挂多台 485 设备时，先扫出哪些从站号是活的
地址是 0 基的（厂家手册写 40001 时这里填 0）。 RTU 透传设备生成点表后，添加设备时协议要选 modbus-rtu-tcp，IP/端口填盒子的。 工具只读不写——绝不碰写功能码，写错地址会改掉设备参数。
地址十进制十六进制变化

第三步 · 点表 JSON（贴到「新增设备」的点表框）

生成后点复制 → 设备监控 → 新增设备 → 点表框里全选粘贴。 然后把 name 改成人话、role 改成实际角色： 状态点 role=status、产量计数 role=count、报警字 role=alarm、普通数值 role=value。 dataType 先按 u16 试，值超过 65535 或对不上再查手册（可能是 u32/浮点）。
