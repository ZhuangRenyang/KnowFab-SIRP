# 不改程序、不装数据库、不要团队、不要年费：一个电工写的工厂系统

不改 PLC 程序，不装数据库，不要团队，不要年费。

一个安装包，全厂的机器全进 ERP。

还有一个 AI，每天早上一份生产日报，它自己写。

这是我这半年做的东西，叫 **KnowFab-SIRP**。

---

## 一、为什么做这个

我干过几年电气，后来自己学了写代码。

在车间里见过太多这样的情况：老板问今天做了多少件，班组长说"大概三千多吧"，仓管翻本子说"账上有五千"，最后谁也不敢拍板。

而实际上，**PLC 里一直有个寄存器在涨，那个数就是产量**。它一直在那儿，只是没人去读。

电气的人知道读哪个寄存器，但不会做界面；
程序员会做界面，但不知道寄存器在哪。

我两边都干过，就想把这条路打通。

---

## 二、市面上的系统，只做到"能看"

我研究过一圈，工厂要想看数据，基本是两条路：

**第一条，组态软件**（组态王、力控、WinCC 这一类）。
能看，能画趋势，能报警。几万块授权，还得找集成商来实施。
但它基本停在"看"——大屏一挂，产量一显示，就到头了。

**第二条，云 MES**。
能管生产、管工单，功能很全。但要上云、按年付费、实施三个月。
中小厂很难扛住这个成本，而且很多厂网络条件根本不允许。

中间那一格是空的：

> **机器做一件 → 产量涨 → 库存加 → 单据开 → 报表出。**

这一段，市面上是断的。组态软件不做业务，MES 要定制开发。

我做的就是这个缺口。

## 三、这套系统能干什么

一句话：**设备动作，账上跟着动。**

具体是这么一条链：

1. **接设备** —— 加一台设备不用写代码，选个模板、填个 IP，点表里告诉系统哪个地址是产量、哪个是运行状态、哪个是报警
2. **算产量** —— 老厂 PLC 寄存器里可能是几十万的历史累计，不用清零，系统按增量算，自动得出"今日产量"
3. **进库存** —— 每做一件，成品仓库存自动加一件
4. **开单据** —— 自动生成一张"生产入库单"，来源写着设备名
5. **出报表** —— 经营报表一键导 Excel

中间不需要人抄、不需要人填、不需要月底对账。

另外还有：

- **车间大屏**：24 小时产量曲线，哪个小时掉了看得见；故障原因和处理建议直接置顶
- **报警翻译**：伺服报 03，它直接写"过载，检查机械负载"，新人不用翻手册
- **AI 早报**：每天早上一份日报，昨天的产量、停机、电费，AI 写成一段话（数据本地算，AI 只负责润色）
- **远程控制**：继电器、启停、点动这些开关量能下发（默认关闭，点位级授权，每次下发都有审计日志）

## 四、技术上几个刻意的选择

这部分给同行看。

**1. 全程只读，不改 PLC 程序**
只用功能码 3（读保持寄存器）和 2（读离散输入）。不写、不下发、不改梯形图。
现场最怕的就是"上了系统，机器反而不敢开"——这个顾虑从架构上就消掉了。

**2. 一个 jar 包，数据库内置**
不用 Docker，不用自己装 MySQL（安装包带了数据目录），双击就能跑。
车间那台旧电脑也能装。

**3. 断网也能用**
数据全在本地。车间网络再差、甚至不连外网，系统照跑。
这一点在这个行业里比什么都重要——很多厂根本不允许设备数据出厂。

**4. 多协议 + 点表驱动**
Modbus TCP / RTU、OPC UA、串口 485。
老设备没网口？加个几十块的 485 转以太网模块，系统里选"RTU over TCP"就通了。
接新设备只改点表（一段 JSON），不改一行代码。

**5. 开源，AGPL-3.0**
源码全在 GitHub 和 Gitee 上。不锁定供应商，客户想改哪都行。
闭源商用、SaaS、白标需要商业授权。

## 五、谁适合用

- **中小工厂**：想看清产线，但不想花几十万上一套 MES
- **设备集成商 / 电气工程公司**：给客户做方案时，缺一个能落地的数据层
- **电工、维修师傅**：懂现场，想学着自己做点东西
- **独立开发者**：想找一个真实的工业场景练手

## 六、我一个人做不完，想找人一起

这套系统我一个人写的，前后花了不少时间，但一个人做不完。

现在最缺三样：

**一是更多协议驱动。**
三菱、汇川、台达、欧姆龙、信捷——谁现场有这些设备，我最想要。加一个驱动就是加一个类，不难。

**二是电气师傅帮我验证。**
不同品牌的报警字怎么对应、点表怎么配最省事，你们比我懂。你们的一句话，能省我一周的猜。

**三是前端和报表。**
我界面做得一般，会 Vue 的兄弟来改，我特别欢迎。报表模板也缺。

代码全在，改哪都行。提 issue、发 PR、进群骂我都行。
