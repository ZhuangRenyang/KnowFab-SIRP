## 【能做什么 · 现在给他们看东西】

先从这台机器开始。

这是设备列表。加设备不用写代码，选个模板、填个 IP 就行。

这是点表——告诉系统，哪个地址是产量，哪个是运行状态，哪个是报警。

这是设备卡片，今日产量、运行状态、报警，一眼看清。
这个「今日产量」，是从 PLC 的累计值里算出来的。
老厂的寄存器里可能是几十万，**不用清零 PLC，它自己算增量**。

这是车间大屏。二十四小时的产量曲线，哪个小时掉了，一眼看见。
出了故障，**原因和处理建议，直接顶在最上面**。

最后，产量会进库存。每做一件，库存自己加一件，**入库单自己开一张**。

…

## 【为什么做 · 还是人脸，PLC 放桌上】

我干了几年电气，见过太多这种情况：
车间想知道今天做了多少件，还得靠人数、靠人记。
但 PLC 里其实一直有个数在涨——那就是产量，只是没人去读。

电气的人知道读哪个寄存器，但不会做界面；
程序员会做界面，但不知道寄存器在哪。
**我两边都干过，就想把这条路打通。**

…

## 【有什么不一样 · 回人脸，六条，每条停半秒】

跟常见方案比，有几个地方不一样。

第一，**不改 PLC 程序**。全程只读，不写寄存器。

第二，**一个安装包，数据库自带**。不用你自己装数据库，也不用 Docker。

第三，**断网也能用**，数据全在自己电脑里。

第四，**新机老机都能接**。Modbus、OPC UA、485，老设备加个几十块的转换盒就行。
而且除了读，**也能下发控制**——继电器、启停、点动都能远程操作，不过默认是关的。

第五，**带 AI**。报警码它翻成人话，伺服报 03 直接写「过载，检查机械负载」；
每天早上一份生产日报，也是它写的。

第六，**开源**。源码全在 GitHub 和 Gitee 上。

…

## 【一起干 · 回人脸，语速放慢，这段最重要】

这东西我一个人写的，但**一个人做不完**。

现在最缺三样：

一是更多协议驱动。三菱、汇川、台达、欧姆龙，谁现场有这些设备，我最想要。

二是电气师傅帮我验证。不同品牌的报警字、点表怎么配，你们比我懂。

三是前端和报表。**我界面做得一般**，会 Vue 的兄弟来改，我特别欢迎。

**代码全在，改哪都行。**

# 录前 5 分钟准备

| 项 | 怎么做 |
|---|---|
| PLC | 通电、网线插好、**RUN 绿灯亮着** |
| 设备卡片 | 提前按几下按钮，今日产量别是 0 |
| 库存页 | 开在「成品一仓 · P-001 六角螺栓 M8」那行 |
| 单据页 | 确认最新一张是「生产入库」，来源写着设备名 |

| 浏览器 | 缩放 **125%**，F11 全屏，关掉所有通知 |
| 机位 | 手机竖屏架好，离脸 40cm，眼睛看镜头 |

# 念的时候记住四件事

1. **语速正常偏慢**——讲技术要让人听懂，别学短视频喊
2. **每段之间停 1 秒**——剪辑时这点空隙能救命
3. **数字咬清楚**：几十万、一个下午、03
4. **说错别停**，继续说，剪掉那一句就行

# 三条不要

| 不要 | 原因 |
|---|---|
| 不要说「我现在演示一下控制」 | 手上没继电器，说了观众等不到画面 |
| 不要说「不用数据库」 | 实际是 MySQL 内置，说"内置"才专业 |
| 不要背稿背到像念课文 | 每句看一眼提纲，用自己话顺出来 |
