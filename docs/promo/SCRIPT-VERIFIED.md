## 【演示 1 · 设备与产量】【可演示】

（屏幕：设备列表 → 设备卡片）

加设备不用写代码。选个模板，填个 IP，点表里告诉它哪个地址是产量。

（指今日产量）

这个数是从 PLC 的累计寄存器算出来的。
老厂的寄存器里可能是几十万——**不用清零，它自己算增量**。

> 出处：`ProdRollup` 增量统计，计数器变小时按重置处理。

## 【硬货 1 · 报警码翻人话】【可演示／可口述】

（切报警页，或只口述）

伺服报警，屏幕上不是一串数字，是中文：

「过载，检查机械负载」。

台达、三菱伺服的报警码内置了，加品牌就是加一个文件。

> 出处：`AlarmCodeDict` + `resources/alarmcodes/*.json`（delta-servo、mitsubishi-servo）。
> **限制**：只有这两个品牌内置，其它品牌靠 AI 猜——话本里别说"支持所有品牌"。

…

## 【硬货 2 · 基本电费怎么交更划算】【只能口述】

（没电表数据就只讲，别演）

大工业电价有两块：电度电费 + 基本电费。
基本电费可以按容量交，也可以按需量交——**选错了一年差几万**。

系统会把这个月的最大需量算出来，两种方式的价钱摆在一起给你看，
还会告诉你离合同需量还剩多少。

> 出处：`demand/DemandService` + `DemandConfig.demandCost / capacityCost`。
> **这条是全片最值钱的一句**——老板听得懂，而且真能省钱。

…

## 【硬货 3 · AI 能查数据】【只能口述】

（不演示）

AI 不是摆设。它接了七个查询工具：
库存、产线产量、设备状态、未处理报警、采购订单、销售订单、应收应付账龄。

你问它「这周哪台设备产量掉得最多」，它自己去查、自己算。

而且**分权限**：班组长只能查产量和设备，财务数据要经理以上。

> 出处：`ai/AiChatService.tools()`（7 个 Tool + roles 过滤）。

…

## 【差异 · 五条，每条停半秒】

跟常见方案比：

第一，**全程只读，不改 PLC 程序**。

第二，**一个安装包，数据库自带**。

第三，**断网也能用**，数据不出厂。

第四，**新机老机都能接**，老设备加个几十块的转换模块就行。

第五，**开源**，源码全给，不锁定。

> 五条都在能力清单里，没有一条是编的。

# 话本对照表：能说 / 不能说

| 想说的 | 能不能说 | 为什么 |
|--------|---------|--------|
| 不改 PLC 程序 | ✅ | 只读功能码，代码里没有写操作路径 |
| 一个安装包 | ✅ | 内置本地数据库（MariaDB 11.4，MySQL 协议兼容，独立 3307 端口） |
| 断网能用 | ✅ | 全本地 |
| 新机老机都能接 | ✅ | Modbus TCP/RTU/RTU over TCP/OPC UA |
| 全进 ERP | ✅ | 采购/销售/库存/财务/产线/报表都有 |
| 报警码翻人话 | ✅ 但要限定 | 只有台达、三菱伺服内置 |
| AI 查数据 | ✅ 但不能演 | 要配 Key |
| 基本电费对比 | ✅ | 真功能，老板最听得懂 |
| 在线升级、双源兜底 | ✅ | 升级包有签名 |
| 算 OEE | ❌ | 只有可用率，OEE 要三要素 |
| 支持所有品牌报警 | ❌ | 只有两个伺服品牌 |
| 现在就有 AI 早报 | ❌ | 没配 Key |
| 成本核算 | ❌ | 轻量 ERP，没有成本核算 |
