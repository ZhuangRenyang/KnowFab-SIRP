# 项目介绍片脚本（真诚版 · 面向同行）

> 受众：**电气工程师 / 工控从业者 / 程序员**
> 目的：让他们知道**这是什么、能干什么、有什么不一样、怎么一起干**
> 调性：不骂人、不搞情绪、不表演。**技术人的坦诚 + 硬货**。
> 形式：出镜 + PLC 实物 + 屏幕演示（三机位，见 MADMAN-DEMO-SCRIPTS.md）

---

## 先说清一件事（这条决定成败）

**你的项目灵魂不是"省钱"，是"把两个行业接起来"：**

> **电气的人懂设备，但不会写代码；程序员会写代码，但不懂设备。**
> **我两边都干过，所以我把这条路打通了。**

这句话对两类人都有杀伤力：

| 受众 | 听到这句话的反应 |
|------|----------------|
| 电气工程师 | 「终于有人懂现场了，不用被程序员问'你的 PLC 为什么不能返回 JSON'」 |
| 程序员 | 「终于有个能落地的工业项目，不用做那种假数据 Demo」 |

**整条视频都围绕这一句展开**，别跑偏。

---

## 黄金结构（五分钟能讲清任何项目）

```
① 我是谁 + 这是什么        （8 秒，一句话）
② 为什么做它               （12 秒，一个真实场景）
③ 它能做什么               （20 秒，屏幕演示，边操作边说）
④ 它有什么不一样           （18 秒，技术差异化，硬货）
⑤ 上手有多容易             （10 秒，一条命令）
⑥ 一起干                   （15 秒，缺什么、欢迎谁）
⑦ 收尾                     （5 秒）
```

## 完整脚本（90 秒）

### 【0-8s】机位 A · 我是谁 + 这是什么

**画面**：人脸，手里拿着 PLC

**台词**：
> 我是做电气出身的，后来自己学了写代码。
> 这套系统叫 **KnowFab-SIRP**，一句话说：**接上 PLC，让所有机器都报产量。**

**字幕**：
```
电工出身 · 自学编程
KnowFab-SIRP
接上 PLC，让所有机器都报产量
```

---

### 【8-20s】机位 A → C · 为什么做它

**画面**：人脸说两句 → 切 PLC 特写（手指点着寄存器位置）

**台词**：
> 我在现场见过太多次这种情况：
> **车间想知道今天做了多少件，得靠人一个个去数、去记。**
> 而 PLC 里其实一直有个寄存器在涨——**它每天都在记录产量，只是没人去读。**
>
> 电气的人知道读哪个寄存器，但不会做界面；
> 程序员会做界面，但不知道寄存器在哪。
> **我两边都干过，所以想把这条路打通。**

**字幕**：
```
PLC 里一直有个寄存器在涨
那就是产量
只是没人去读
```

> 这段是**情绪的真来源**：不是骂谁，是说"这事本来能解决，只是两边没接上"。

---

### 【20-40s】机位 B · 它能做什么（屏幕演示，边操作边说）

**演示顺序（一定要按这个顺序，逻辑最顺）**：

| 时间 | 屏幕画面 | 台词 |
|------|---------|------|
| 20-25s | 设备列表 → 新增设备 → 选模板「西门子 S7-200 SMART」 | 「加设备不用写代码，选模板、填个 IP 就完事。」 |
| 25-30s | 点表列表：地址、数据类型、角色（产量/状态/报警） | 「点表就是告诉系统：哪个地址是产量，哪个是运行状态，哪个是报警。」 |
| 30-35s | 设备卡片：今日产量 + 累计 + 状态 | 「它自己算今日产量——寄存器里可能是几十万的历史累计，系统只按增量算。」 |
| 35-40s | 大屏（全屏）：24 小时曲线 + 故障原因置顶 + 设备网格 | 「这是给车间大屏的页面，纯 HTML，不装任何插件，浏览器打开就是。」 |

> **操作要慢**，每个页面停 3 秒以上，让人看清。鼠标别晃。

---

### 【40-58s】机位 A + B · 它有什么不一样（这段是核心差异）

**台词**（一条一条说，每条配一个屏幕证据）：

> 跟常见方案比，它有几个地方不太一样：
>
> **第一，不改 PLC 程序。** 全程只读，不写寄存器、不下发指令——现场最怕的就是"上了系统，机器反而不敢开"。
>
> **第二，单文件部署。** 一个 jar 包，不用 Docker、不用装数据库，双击就能跑。**车间那台旧电脑也能装。**
>
> **第三，断网也能用。** 数据全在本地，车间网络再差、甚至不联网，照样跑。
>
> **第四，多协议。** Modbus TCP / RTU、OPC UA、串口 485——**老设备加个几十块的转换盒也能接。**
>
> **第五，开源。** AGPL 协议，源码全在 GitHub 和 Gitee 上。

**屏幕证据**（每条配一张，切得快）：
1. 点表里 role 字段 / 只读标识
2. 安装目录截图（一个 jar）
3. 断网状态下的系统界面
4. 驱动列表（协议支持）
5. 仓库首页（Star / 协议）

---

### 【58-68s】机位 B · 上手有多容易

**画面**：终端一条命令 → 启动日志 → 浏览器打开首页

**台词**：
> 装起来就一条命令，Windows 和 Linux 都行。
> 我自己的记录是**从零到看见产量，一个下午**——包括找 PLC 的 IP、配点表。

**字幕**：
```
一条命令
一个下午，从零到看见产量
```

---

### 【68-83s】机位 A · 一起干（**这段最重要，决定有没有人真的来**）

**台词**：
> 这套东西我一个人写的，但**一个人做不完**。
>
> 现在最缺的是三样：
> **一是更多协议驱动**——三菱、汇川、台达、欧姆龙，谁的现场有这些设备，我最想要。
> **二是电气师傅帮我验证**——不同品牌的报警字、点表怎么配，你们比我懂。
> **三是前端和报表**——我界面做得一般，会 Vue 的兄弟来改，我特别欢迎。
>
> 如果你也在工厂里、或者你也写过工业软件，
> **欢迎来一起做，代码全在，改哪都行。**

**字幕**：
```
缺：更多协议驱动
缺：电气师傅帮忙验证
缺：前端 / 报表
代码全在，改哪都行
```

> **说"我界面做得一般"这句话很重要**——技术人示弱，比吹牛更能招来人。

---

### 【83-90s】机位 A · 收尾

**画面**：人脸，把 PLC 放下

**台词**：
> **让所有机器都报产量。**
> GitHub 和 Gitee 搜 **KnowFab-SIRP**，文档、安装包、源码都在上面。
> 有问题在群里问，或者直接提 issue。

**字幕**：
```
让所有机器都报产量
KnowFab-SIRP · GitHub / Gitee 可搜
```

## 拍摄与剪辑要点（针对"好好介绍"这个调性）

| 项 | 要求 |
|---|------|
| **语速** | 正常偏慢（讲技术要让人听懂），**不要学短视频那种吼** |
| **语气** | 平静、坦诚，像给同行讲你做的东西 |
| **眼神** | 看镜头，别飘 |
| **背景** | 工作台 / 机柜 / 电脑，干净但不必刻意 |
| **字幕** | 关键词加粗（型号、协议、数字），一行 ≤ 14 字 |
| **BGM** | 极轻的科技感，音量 15%（**技术片不需要 BGM 抢戏**） |
| **切换** | 每 4~6 秒换机位（比情绪片慢，要给观众看懂的时间） |
| **时长** | 90 秒；发抖音可剪 45 秒版（去掉第④段的后三条） |

## 配套文案（发布时直接用）

**标题**：
- `电工出身，我一个人写了套工厂数据系统，现在开源了`
- `接上 PLC 就能看产量：一个电气人写的开源 MES`

**正文**：
```
电工出身，自学写代码，一个人做了套工厂数据系统 KnowFab-SIRP。

接 PLC 读产量、状态、报警；产量实时上屏，联动库存和入库单。
不改 PLC 程序（只读）、单文件部署（不用 Docker）、断网也能用。

多协议：Modbus TCP/RTU、OPC UA、485。
开源 AGPL，源码在 GitHub / Gitee，搜 KnowFab-SIRP。

最缺的是更多协议驱动，和电气师傅帮忙验证不同品牌。
会 Vue 的、懂现场的，都欢迎一起改。
```

**置顶评论**：
```
源码 + 安装包 + 文档：GitHub 和 Gitee 搜 KnowFab-SIRP。
想参与开发的，说下你会什么、现场有什么设备，我们分工。
```
