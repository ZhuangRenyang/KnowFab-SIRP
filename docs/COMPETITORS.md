# 竞品与参照（COMPETITORS）

> 用途：给客户讲方案时的定位话术 + 产品决策时的对照。
> 信息截至 2026-10-30（hm-MES 一节基于其 Gitee 仓库主页实测抓取），来源为各官网公开页面；价格与功能以对方最新页面为准。

## 一、快工单（kgd.ltd）——最直接的相邻竞品

**山东德萨大数据股份有限公司**（清峦福兴集团旗下，2015 年创立）旗下品牌，
定位「轻量化 MES / 生产管理系统」，官网主推：生产管理、售后管理、设备维保、CRM、
车间大屏、数字孪生、智能硬件（扫码枪/终端）、AMR 搬运机器人。
AI 层为「灵犀 AI」（DeepSeek 驱动）：AI 排产、AI 质量专员、AI 采购专员、
AI 成本会计、AI 经营参谋等"数字员工"。宣称服务 56000+ 家企业，10 余家世界 500 强。

### 1. 与我们的本质差异

| 维度 | 快工单 | 知造 SIRP（我们） |
|---|---|---|
| **数据从哪来** | **人扫码报工**：工单流转、扫码计时计件、工序进度靠扫码回流 | **设备直连自动采集**：Modbus TCP/RTU、485 透传盒、老设备行程开关计数——机器自己报数，不依赖工人扫码 |
| **部署方式** | 云端 SaaS，注册开通，数据在对方云上 | **私有化部署**在客户自己服务器（jar + MySQL，一条命令安装），数据不出厂 |
| **功能重心** | 工单、工序派工、计件工资、售后维保、CRM | 设备监控、产线计数→自动生成入库单、进销存财务一体、能耗分项计量、报警 |
| **没有的** | 设备协议级采集、能耗分项计量、计数自动入库（人工扫码计数口径） | 工序级派工、计件工资、售后/CRM |
| **AI** | 已落地：灵犀 AI 数字员工（按岗位：生产/质量/采购/成本/经营参谋） | 规划中（DH-46/48）：按角色收口权限的查库助手，支持本地/云端/可关闭 |
| **硬件** | 卖硬件：扫码枪、看板终端、AMR 机器人 | 不卖硬件，但兼容市面各种 485 网关/采集盒（帮客户选型） |
| **目标客户** | 有完整工序流转、要管工人计件的装配/加工厂 | 设备多、老设备多、想"机器自动报数"的加工/注塑/冲压/机加工厂 |

**一句话定位：他们管"人和单据的流程"，我们管"机器的数据和账"。**

### 2. 销售话术（正面打这两点）

- **采集方式**："快工单让工人扫码，扫码的前提是人到、记得扫、不造假。我们是让机器自己报数——
  老冲床装个行程开关、新机床走网口，产量自动进系统，工人该干嘛干嘛，数据还不会错。"
- **数据归属**："他们是 SaaS，你的产量、订单、客户资料在别人的云上；
  我们装在你自己的机房，一条命令安装，断外网照常用，数据随时 mysqldump 拿走。"
- **账是一体的**："他们记产量要再对接 ERP；我们机器一计数，成品入库单自动生成，
  库存、应收、报表用的是同一本账，不存在两套系统对不上。"

### 3. 他们赢了我们就让（别硬碰）

客户明确要**工序级派工、计件工资核算、售后报修、客户 CRM** 时，他们成熟得多——
这些我们不做（ROADMAP 边界），可以坦诚说"这快工单更合适"，或按客户体量谈合作/集成。
硬凑一个半成品模块只会砸口碑。

### 4. 值得抄的作业（产品与销售两侧）

1. **灵犀 AI 的"按岗位配数字员工"**：生产/质量/采购/成本/经营参谋各一个，
   每个岗位有自己的口径和权限。这与我们 DH-46/48 的"按角色收口查库"同构，
   且他们验证了市场接受度——AI 助手按角色给答案，而不是一个万能聊天框。
2. **"先从一件最烦的活开始"**：不推全套，先跑通一个场景再铺开。交付话术直接借用。
3. **部署速度当卖点**：10 分钟部署、1 分钟学会。我们的一键安装已具备，README 要这样表达。
4. **免费试用先行**：先开通再谈钱。我们的演示数据脚本（seed-demo）+ 试用授权可以支撑同样打法。

## 二、hm-MES（Gitee imdreamer/hm-MES）——开源赛道最近的对手（2026-10-30 拆解）

**出身与模式**：作者 imcoder 基于「章鱼兄弟 MES-Springboot」二次开发的工业化版本，AGPL 开源。
变现走**服务制**：安装部署 / 讲解培训 / 实施 / 运维 / 定制开发，无公开标价。
运营起步早：演示站（看板+管理端+对接 ERP 三套）、B 站演示视频矩阵、两个 QQ 交流群
（其一已满员）、CSDN 软文；同作者多产品线：smart-mes（若依版，"开源市场长期霸屏"）、
C# iMES、WMS、C# WPF MES+WMS、低代码看板设计器。

### 1. 逐功能对比（含接入路径）

| 维度 | hm-MES | 知造 SIRP（我们） |
|---|---|---|
| **采集架构** | **独立 IoT 组件程序**（netty，单独启动）+ MQ（RabbitMQ，可屏蔽）与主程序解耦 | **采集内置在主程序**：单 jar，无独立进程、无 MQ、无 Redis |
| **协议广度** | 宽：udp / tcp / http / mqtt / websocket / modbus / 欧姆龙 Fins / 西门子 PLC / tdEngine | 窄但准：modbus-tcp / modbus-rtu（本地串口）/**modbus-rtu-tcp（485 串口服务器透传）**/ sim 模拟 |
| **485 转网线接入** | 理论可经 modbus 组件对接，但配置落在组件代码/配置文件，无界面 | **设备管理界面直接选「modbus-rtu-tcp」**：填串口服务器 IP + 端口 + 从站号即接入；485 设备模板、扫描发现、点表 JSON、IP 台账全套界面化 |
| **哑设备（无接口老设备）** | 无路线（采集不到就手动报工） | **继电器 + 行程开关计数**：老冲床装个开关就自动报数 |
| **设备接入门槛** | 需理解 netty 组件、MQ 解耦、多进程部署 | 界面化三步：扫描 → 探测 → 点表；或选模板只填 IP |
| **ERP / 进销存** | **对接外部 ERP**（作者另一套演示站，需另行部署；仓库/物料/产品/BOM/订单全靠接口传） | **内置**：计数 → 自动生成成品入库单 → 库存/应收应付/账龄/报表同一本账 |
| **部署形态** | mysql + redis + rabbitmq(可选) + nginx(看板) + IoT 组件 + 主程序，多进程多组件 | 单 jar + MySQL；另有**免环境便携版**（自带 JRE+MariaDB，一条命令） |
| **产量口径** | 采集值 → 报工 / 看板展示 | 计数差分 → 小时产量表 → 日/月/年/综合四表（和=KPI）→ 入库联动 |
| **许可** | AGPL | AGPL + 商业双轨（同路数） |
| **运营** | 演示站 / 视频矩阵 / QQ 群，起步早生态成熟 | 起步阶段：演示数据脚本、README 七语言、视频待拍 |

### 2. 他们强在哪（别硬碰）

- **协议广度与 IoT 解耦架构**：mqtt/fins/tdEngine 这些我们不做——客户有 IT 团队、协议特殊时他们合适
- **产品线矩阵与先发生态**：多语言版本、霸屏项目、满员社群——冷启动阶段硬刚流量必输
- **低代码看板设计器**：我们的大屏是固定模板

### 3. 我们赢的就三条（也正好是中小工厂付钱的点）

1. **一本账**：hm-MES 的仓库/物料/BOM/订单全靠对接外部 ERP——客户实际要维护两套系统 + 接口。
   我们机器一计数，入库单、库存、应收应付、报表同源，不存在"两套系统对不上"
2. **部署与接入门槛**：他们起步就是 mysql/redis/IoT 组件/nginx 四件套，接 485 要配组件；
   我们一条命令装完，485 买几十块的串口服务器，界面里选协议填 IP
3. **哑设备**：他们没有路线；我们有继电器 + 行程开关计数——这是"其他家都做不了"的镜头

### 4. 话术

- 定位差异："hm-MES 是给有 IT 团队的厂做二次开发的脚手架——ERP 自己对接、采集组件自己起、
  MQ 自己装；我们是装完就能用的一体化系统，机器自动报数、库存自动对账"
- 485 场景："温控表、电表这些 485 设备，买个几十块的串口服务器转成网线，
  我们界面里选 modbus-rtu-tcp、填个 IP 和从站号就接进来了，不用写一行代码"
- 哑设备："你那台没有网口的老公冲床他们怎么办？手动报工。我们装个行程开关，每打一件自动 +1"

### 5. 值得抄的作业

1. **演示站三件套**（看板 + 管理端 + 对接 ERP 各一个公网地址）：注册个云主机就能挂，
   视频里给观众"自己登录玩"的入口
2. **B 站视频矩阵 + QQ 群**：讲解视频获客已被验证；我们拍完第一批视频后建群
3. **多产品线同作者打法**：等 SIRP 站稳后再考虑第二产品线，现在专注单点

## 三、jshERP——功能参照（不是竞品）

开源进销存 ERP（depot_head/depot_item 单头+明细、库存=流水累计的口径已被我们验证并沿用）。
我们的 ERP 模块（DH-42~54）全自研但**口径对齐**它：单据头+明细行、作废不删数据、
库存预警按全厂合计。它没有设备联网与生产采集——这是我们与"纯 ERP"的差异点。
