## ★ 当前方向（2026-11-06 定调，依据 `docs/decisions/ADR-001-product-direction.md`）

> **对外定位**：设备数据直连的轻量 MES + 进销存。产量不用人录，库存和单据永远对得上。
> **不说**「ERP + MES + IoT + AI 四合一」「Manufacturing OS」——定位抬高会拉长销售周期。
> **切口按场景不按行业**：「几十台设备、老板要随时知道产量和库存对不对得上、不想雇文员录数」的厂。

**本轮只做三件事**（其余一律按 ADR-001 的「不做清单」挡住）：

| 优先级 | 事项 | 编号 | 一句话理由 |
|--------|------|------|-----------|
| P0 | 收口交付（关演示数据 / 现场参数+断网演练 / 真实仓库地址 / 备份演练） | A 段 4 项 | 功能已完整，装不上或没演练过等于白做 |
| P1 | **工作流最小版**（审批 + 派工 + 通知 + 让 AI 能调写操作） | DH-85 | 「AI 只能建议」的根因是**没有可被调用的动作层**，这是唯一的产品差异点 |
| P2 | **需量瞬时的边缘缓存**（只针对电费，不做通用边缘平台） | DH-86 | 累计量断网不丢；只有瞬时峰值会漏，而需量按峰值计费 → 真算错钱 |

**明确不做**（写了就不改，要改先改 ADR）：平台化/开放 API/插件市场、MQTT/多厂/多租户、财务总账凭证、通用边缘计算平台、预测性维护、工序路线（等客户确认为多工序）、二次抽样/加严自动转移（等客户要求）。

### 依赖顺序（为什么这么排）

```
产线计数(DH-40/41) ──→ 仓库+主数据(DH-42/43/44) ──→ 销售查询(DH-45)
                                                      │
AI 框架(DH-46，可提前做，复用现有配置) ──────────────→ AI 助手(DH-47/48)
```

AI 助手放最后不是不重要——它要查产线产量和库存，地基越厚它越有用；
DH-46 框架（多厂商+开关）可以提前做，改造成本低（现有一套 AiConfig 已是 OpenAI 兼容）。
