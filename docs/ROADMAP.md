# 待办清单（ROADMAP）

> 更新：2026-10-26 21:10
> 用法：交付前逐条勾 A 类；谈单时按 B 类排序报价；C 类只在有余力时动。
> 编号规则：`DH-xx`，新增只往后加，不复用已关闭的号。

图例：**P0** 阻塞交付 / **P1** 能加价 / **P2** 技术债
状态：`待做` / `进行中` / `待客户确认` / `已完成`

**验证纪律（2026-10-28 起）**：每完成一个功能，固定三步——
`python tools/seed-demo.py`（幂等铺演示数据）→ `python tools/smoke-all.py`（全功能接口冒烟）
→ `python tools/selftest.py`（契约/权限回归，40 条），全绿再提交。
理由：功能越堆越多，"改一处崩别处"靠人点是防不住的；演示数据还能让每个状态在界面上看得见。

### 依赖顺序（为什么这么排）

```
产线计数(DH-40/41) ──→ 仓库+主数据(DH-42/43/44) ──→ 销售查询(DH-45)
                                                      │
AI 框架(DH-46，可提前做，复用现有配置) ──────────────→ AI 助手(DH-47/48)
```

AI 助手放最后不是不重要——它要查产线产量和库存，地基越厚它越有用；
DH-46 框架（多厂商+开关）可以提前做，改造成本低（现有一套 AiConfig 已是 OpenAI 兼容）。
