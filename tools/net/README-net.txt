知造 SIRP · 电脑接 PLC 不断网工具包
====================================

场景：一台电脑既要用 WiFi 上网，又要用网线连 PLC。
不正确的配法会导致「插上网线就没网」——通常是网关/DNS/跃点打架。

--------------------------------------------------------------------------
【先看懂这一条，能省掉你 90% 的烦恼】
--------------------------------------------------------------------------
  本机 IP 的数量 = **网段数量**，不是设备数量。

  1000 台设备各用不同 IP（192.168.10.1 ~ 192.168.10.1000）**完全正常**，
  只要它们在**同一个网段**。这时本机一个 192.168.10.100/24 就够连全部
  1000 台 —— 系统按路由表自动选源地址，不需要 1000 个本机 IP。

  ⇒ 所以「设备变多要改本机 IP」是**误解**。真正要改的只有一种情况：
     **PLC 换到了另一个网段**（比如新产线用 192.168.20.x）。
  ⇒ 本工具包的做法：**一次把要用的网段全配好**，之后加设备不用再动本机网络。

--------------------------------------------------------------------------
【2026-11-07 语义变更 —— 老用法请注意】
--------------------------------------------------------------------------
  旧版 plc-on 是把网卡上**所有** IPv4 地址删掉、关掉 DHCP、改设一个静态 IP。
    ⇒ 主 IP 被换掉 ⇒ 必须先 plc-off 才能恢复上网；
      换 PLC 网段还要改脚本参数重来 —— 这就是「每次接 PLC 都要改本机 IP」。

  新版是**保留主 IP 不动**，只**追加**静态 IP 别名（可一次配多个网段）。
    ⇒ 主 IP 从来没被改过 ⇒ 上网不受影响、不需要来回切 plc-on/plc-off；
      加设备/加网段时再跑一次 plc-on 即可（幂等，已存在的会跳过）。

--------------------------------------------------------------------------
【Windows：三个文件，双击即用】
--------------------------------------------------------------------------
  plc-diag.bat   诊断（只读，不改配置）
                 插上网线后运行，自动判断是哪种断网原因
                 （A 默认网关被抢 / C DNS 抢答 / D 代理 TUN），
                 并在目录里生成 plc-diag-日期.txt，可发给工程师。
                 2026-11-07 新增一节「本机网段清单与目标可达性」：
                 直接列出本机有哪几个网段、目标 PLC 能不能直连 ——
                 以前这件事只能靠试错（改 IP → 连 → 不行 → 再改）。

  plc-on.bat     配置 PLC 网段可达（需要管理员）
                 **追加** IP 别名（不删现有地址、不关 DHCP、别名不带网关），
                 跃点 9000（保证 WiFi 优先上网），关掉共享探测绑定，
                 最后自动 ping 各 PLC 验证。

  plc-off.bat    撤销别名（需要管理员）
                 **只删 plc-on 加过的别名**（靠 .plc-aliases 清单精确回滚，
                 不会误删你自己手配的 IP），跃点恢复自动，绑定恢复。
                 ⚠️ 主 IP 与 DHCP 一概不动 —— 因为它们从来没被改过。

--------------------------------------------------------------------------
【Linux：两个脚本（生产环境用这个）】
--------------------------------------------------------------------------
  tools/net/plc-on.sh    sudo ./plc-on.sh
  tools/net/plc-off.sh   sudo ./plc-off.sh

  ⚠️ Linux 的已知限制：手工加的 IP 别名在
     `systemctl restart NetworkManager` / `systemctl restart systemd-networkd`
     或网卡重新 up 之后**可能被清掉**。
     ⇒ 要长期生效，请按 plc-on.sh 结尾提示把它做成一个 oneshot 服务。

--------------------------------------------------------------------------
【常用命令】
--------------------------------------------------------------------------
  Windows（ps1 顶部可改默认值，或命令行传参）：

    plc-on.bat                                   用默认网段 192.168.10.100/24
    plc-on.bat -s 192.168.20.100/24               只加这一个网段
    plc-on.bat -s 192.168.20.100/24 -s 192.168.30.100/24    一次加多个
    plc-on.bat -p 192.168.10.1 -p 192.168.20.1   要 ping 验证的 PLC

    plc-diag.bat -TargetIps 192.168.10.1,192.168.20.1   判定多个目标可达性

  Linux：

    sudo ./plc-on.sh -i eth0
    sudo ./plc-on.sh -i eth0 -s 192.168.20.100/24 -s 192.168.30.100/24
    sudo ./plc-on.sh -i eth0 -p 192.168.20.1

  默认参数：
    PLC 地址     192.168.10.1     ps1 顶部 -PlcIp / sh 的 -p
    电脑别名     192.168.10.100   ps1 顶部 -Ip / sh 的 -s
    网卡名       以太网(Win) eth0(Linux)   参数 -Name / -i

--------------------------------------------------------------------------
【常见坑】
--------------------------------------------------------------------------
  1. （已处理，2026-10-30）PLC 原用 192.168.0.1，与最常见的路由器默认
     地址撞车，导致插线整体断网；现已把 PLC 迁到 192.168.10.1 网段，
     电脑侧 plc-on.bat 同步配 192.168.10.100。
  2. Clash/v2ray 等开 TUN 模式时，插新网卡会抢路由。先退出代理再试。
  3. 诊断必须在「插着线、且断网正在发生」的那一刻运行，拔线状态下
     什么都查不出来。
  4. （2026-11-07）**PLC 换了网段**时，不要改本机主 IP ——
     直接再跑一次 plc-on 加一个新网段的别名即可。
     跑 plc-diag 看「本机网段清单」，它会直接告诉你目标网段在不在。
  5. （2026-11-07）**不要用「禁用/启用网卡」来断电重连** ——
     手工加的别名在网卡重新 up 之后可能被清掉（Linux 尤其明显）。
     要重来就跑一次 plc-on，它是幂等的。
